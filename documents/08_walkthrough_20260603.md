# 변경 사항 요약 (Walkthrough)

작업 관리자에서 높은 GPU 점유율이 노출됨에도 불구하고 프로그램에 0%로 고정되어 나타나던 오류를 해결하기 위해 `GpuMonitor.cs` 의 핵심 수집 로직을 개선했습니다.

## 변경 내용

### 1. 동적 성능 카운터 스캔 및 갱신 방식 도입
* **기존 문제**: 프로그램 시작 시에만 단 한 번 성능 카운터 인스턴스를 가져오고 유지함으로써, 실행 이후에 켜진 고사양 GPU 사용 프로세스들을 아예 감지하지 못했습니다.
* **해결 방안**: 매 `Sample()` 주기마다 `PerformanceCounterCategory.GetInstanceNames()`를 다시 검사하여 `_counters` 딕셔너리를 업데이트합니다.
  - **새로운 인스턴스**: 감지 즉시 `PerformanceCounter` 객체를 생성하고 기준선 생성을 위해 `NextValue()`를 초기 1회 호출해 둡니다.
  - **소멸한 인스턴스**: 딕셔너리에서 제외함과 동시에 `Dispose()`를 수행하여 메모리 및 성능 카운터 핸들 누수를 방지합니다.

### 2. 사용률 계산 방법 개선 (합산 방식)
* **기존 문제**: 특정 GPU 어댑터의 사용률을 계산할 때 각 프로세스 카운터 중 최댓값(`Max`)만을 채택하고 있어 프로세스 간 사용률 합산이 불가능했습니다.
* **해결 방안**: 같은 LUID를 공유하는 GPU 어댑터별로 해당 프로세스들의 사용률 백분율을 모두 **합산(Sum)**한 후 최종적으로 최대 점유율을 도출하도록 개선했습니다. (최종값은 0~100 사이로 안전하게 클램프 처리)

### 3. GPU LUID(어댑터 키) 추출 로직 보정
* `ExtractAdapterKey` 메서드에서 LUID 문자열(예: `luid_0x00000000_0x00017ECB`)의 언더스코어로 인해 전체 범위의 LUID 값이 추출되지 못하는 버그를 개선했습니다. `_phys` 문자열의 경계를 명확히 구분하여 정확한 LUID 고유 키가 매핑되도록 보강했습니다.

## 검증 결과

### 1. 자동 빌드 테스트
`dotnet build` 명령어를 사용하여 컴파일 오류 없이 정상적으로 빌드 완료됨을 확인하였습니다.
```powershell
Build succeeded.
    0 Warning(s)
    0 Error(s)
```

### 2. 리소스 관리 검증
* 매 주기에 동적으로 생성 및 소멸하는 성능 카운터에 대해 매칭 여부를 검토하고, 소멸 시점에 안전하게 `.Dispose()`가 이루어지도록 구조화하여 시스템 리소스 누수를 차단했습니다.
